## 二、新增功能

### 2.1 首页「机器达标监控」改成「一台机器一张卡」（0.2.0）

原来首页只有一行「机器达标监控」入口，点进去才能看到进度。现在首页直接把每台**还没达标**的机器摊开成独立卡片：

- 只收录**未达标、且达标窗口还没过期**的机器；已刷满金额或窗口已过的机器不再占位，首页更短；
- 卡片标题带序号（`机器达标监控（1）`、`（2）`…），右上角是状态胶囊（审核中 / 进行中 / 已完成，按机器当前状态着色）；
- 左列「达标剩余天数」+ 大号天数数字，**剩余 3 天及以内转红**提醒；
- 右列门店名 + 机器号，门店名取装机申请时填的「商户名称」快照，没填则退回机型（如「电签机」）；
- 底部一条达标规则：`从装机之日起 N 天内刷卡累计 X 元 奖励 Y 积分`，窗口天数与奖励积分都取后端下发的任务快照，不再写死；
- 剩余天数**每次打开首页、下拉刷新都按当前时间重算**，不用接口下发时的快照值，避免隔了几天再打开数字偏大；
- 没有需要监控的机器时退回一行入口卡，文案区分「未绑定机器」和「机器均已达标」，点击进「我的机器」。

### 2.2 添加机器页新增「商户名称」（选填）（0.2.0）

装机时可以把门店名字一并填上，位置在「客户手机号」之后、「身份证号后 6 位」之前：

- 选填，最多 64 字，留空**不提交**，不会覆盖装机申请单上已经填过的商户名称；
- 存的是门店名快照，后台装机列表 / 申请详情可见同一字段，后台装机时也能补填；
- 首页监控卡的门店名就取自这里，所以填了对用户自己也有用。

### 2.3 新手达标「双方确认」（0.2.0）

提交达标后不再只等后台人工审核，改为**装机人和机器归属人双方确认**：

- 提交达标后，直接推荐人**装机人**和**机器归属用户**登录都会收到确认弹窗，一次可以勾选多台机器一起确认（默认全选）；
- 弹窗逐台显示门店名·机号、累计流水 / 达标门槛、剩余天数，以及「对方已确认 / 等待对方确认」；
- **每次打开 App、回到前台都会弹**，但自己已经确认过的那台不再出现，已达标或后台已审核的也不再出现，不会反复打扰；
- **双方都确认、且累计流水已达门槛 → 自动置为达标通过并发放奖励**，不用再等人工；
- **累计流水没达门槛 → 不自动通过、不发奖**，弹窗与结果提示会写「流水未达门槛」，仍由后台人工处理；
- 装机人为空、或装机人就是归属人本人时，本人确认即可。

### 2.4 升级提示弹窗（0.2.0）

名下有**冻结中**的装机奖励积分时，每次打开 App 会先问一次要不要升级：

- 弹窗条件：有待定冻结奖励 + **可用积分 ≥ 下一档礼包积分**（L2 为 600 档，已购该档礼包则为 0 积分）+ 还没到 L2；已 L2 不弹；
- 点「立即升级」：后端**自动进入对应档位房间**（扣礼包积分、占位、升到 L1 或 L2），冻结的奖励积分**立即解冻到本人可用余额**；
- 点「暂不升级」：二次确认后，冻结的奖励积分**立即转给直接推荐人**（没有推荐人时发给自己）；
- 点「稍后再说」：本次不处理，下次打开 App 再问；
- 30 天到期自动转推荐人的老规则保留为**兜底**，即使一次都不点也会照常执行；
- 两个弹窗顺序固定：**先升级提示，处理完再弹双方确认**，不会叠在一起。

### 2.5 推广中心精简（0.2.0）

推广中心页只保留「我的推广码」和「推广二维码」两块，**「复制推广链接」下方的统计卡（直推人数 / 已达标 / 累计奖励 / 本月奖励）、三级人数分布、下级明细三个模块不再展示**：

- 页面更短，分享推广码 / 二维码是唯一动线；
- 后端 `GET /user/invite` 与 `GET /user/invite/records` 接口保持不变，数据仍可取，后续需要恢复时会用一个开关常量打开，不用改后端。

## 三、申请 POS 页：品牌 / 类型 / 所属平台不展示（0.2.0）

这三项在 `0.1.9` 开发过程中试做过下拉选择器，最终决定**申请页不再展示**，保持申请流程精简：

- 申请页只保留必填信息，三项下拉整体移除，页面也不再请求字典接口，字典接口异常不会影响提交；
- 后端仍保留这三个字段的接收与校验能力（传了才校验、须为启用中的字典项），历史申请单数据不受影响；
- 结果就是：用户在 `0.1.9 → 0.2.0` 升级后，申请 POS 页的操作和以前完全一样。

## 四、服务端配套变更（必须与本版本一起上线）

0.2.0 的首页监控卡依赖机器列表接口的**出参新增字段**，`GET /pos/machines` 与 `GET /pos/machines/{sn}` 每台机器新增：

| 字段 | 含义 |
| --- | --- |
| `merchantName` | 门店名快照（取自装机申请单，自装机器为 `null`） |
| `installedAt` | 装机完成时间 |
| `dueAt` | 达标窗口截止时间（倒计时基准） |
| `windowDays` | 达标窗口天数 |
| `taskSelfPoints` | 达标可得积分（任务快照） |

另外新增 4 个接口（App 端已在用，后端未更新时弹窗逻辑整体降级为「不弹」）：

| 接口 | 作用 |
| --- | --- |
| `GET /pos/newbie/confirmations` | 我能确认的待达标机器（门店名 / 机号 / 流水 / 门槛 / 剩余天数 / 对方是否已确认） |
| `POST /pos/newbie/confirm` | 多选确认，一次 1~20 台，逐台返回 `confirmed`/`settled`/`reason`/`message` |
| `GET /team/upgrade-prompt` | 升级提示；不满足条件（已 L2 / 无待定奖励 / 积分不够）返回空体 |
| `POST /team/upgrade-prompt/choice` | `choice` = `upgrade`（自动进房并解冻奖励）/ `decline`（奖励立即转推荐人） |

双方确认依赖**新表 `pos_newbie_confirm`**（`task_id` / `user_id` / `role` / `confirmed_at`，唯一键 `(task_id,user_id)`），随发布由迁移闸门执行 `db/migrations/20261120_pos_newbie_confirm.sql` 建表；**跳过迁移直接发新镜像，确认接口会 500**。

生产当前镜像仍是 `9669c3d`（commit `9669c3d`），**未包含**这批字段，所以两种上线顺序的结果不同：

- **先发 App、后端未更新**：首页监控卡照常显示，但门店名退回机型、规则文案缺窗口天数与奖励积分、剩余天数退回接口下发的 `daysLeft` 快照（缓存后可能偏大）；
- **后端已更新**：卡片按新字段完整显示。

建议先部署后端镜像，再上传 App 包，避免用户看到降级后的卡片。

## 六、升级与发布注意

- 安装包为 release 签名（证书 `CN=KQW, OU=Mobile, O=KQW, L=Beijing, ST=Beijing, C=CN`，SHA-256 `3b5c61b4b58fb7970fa0dd57b59768fb1af3c489fa47eecf7a380d4367495b13`），与 `0.1.9`、`0.1.8` 一致，可直接覆盖升级；
- **后台版本记录要从 `0.1.9` / versionCode `10` 改成 `0.2.0` / versionCode `11`**，下载地址指向新包 `https://zhy-h5.citykafei.com/download/kqw-0.2.0.apk`；不改的话 App 冷启动的更新提示只会推到 0.1.9，老用户收不到 0.2.0；
- `0.1.9` 在版本接口上曾配置过一版安装包，那一版是本次改动构建之前的产物，**不含本说明里的功能**，需要用 0.2.0 覆盖；
- release 包默认连生产 `https://zhy-api.citykafei.com`，不含内网明文 HTTP 放行，也不要加 `--dart-define` 覆盖后端地址；
- `--debug` 包与 release 包签名不同，手机上一旦装过 debug 包，必须先卸载才能装正式包。

## 七、已知限制

- 已达标但窗口已过的机器不列入监控（口径为「未达标且未过期」）；是否要把「过期仍未达标」的机器也列出来提醒，待业务确认；
- 自装机器（没有装机申请单）没有门店名快照，卡片显示机型；
- 审核中的机器也会出现在监控里，若业务上希望审核期间不提醒，需要再加一层状态过滤。
